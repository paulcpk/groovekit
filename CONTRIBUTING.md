# Contributing

Thanks for wanting to help with GrooveKit!

## Please open an issue, not a pull request

GrooveKit is maintained by one person, and to keep the design and the code consistent I write the
changes myself. So please **don't open pull requests**: they'll be closed. Instead, open a detailed
issue, and I'll follow up there.

- **Bug report**: [open one](https://github.com/paulcpk/groovekit/issues/new?template=bug_report.yml)
  (labelled `bug`)
- **Feature request**: [open one](https://github.com/paulcpk/groovekit/issues/new?template=feature_request.yml)
  (labelled `enhancement`)

The more detail, the faster I can act on it. A good bug report has:

- what you did, step by step, from opening GrooveKit
- what you expected, and what happened instead
- your GrooveKit version (from the release you downloaded, or the commit you built), macOS version and Mac model
- your audio setup if sound or recording is involved: output and input devices, buffer size, sample rate, any hardware such as a Digitakt
- screenshots or a short screen recording, and if it's about a song, the project folder's `song.json` (zipped)
- if Claude was involved: what you asked, and what the agent did (the Agent tab lists its changes)

A good feature request says what you're trying to make or do, what gets in the way today, and how
you'd like it to work. Examples from other music tools are welcome as descriptions of the workflow.

Please search the existing issues first, and add to one if it's already there.
